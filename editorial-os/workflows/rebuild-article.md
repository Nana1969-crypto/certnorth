# Workflow: Rebuild Article

**Purpose:** genuinely improve a weak article. **Not** a rewrite of the same page in
different words.
**Publication:** requires explicit human approval.

## Sequence
1. **Diagnose** — name the specific weaknesses: thin, unoriginal, outdated,
   templated, poorly sourced, wrong intent. Be concrete.
2. **Identify what is worth preserving** — correct facts, good framings, useful
   sections, existing inbound links and the URL itself
3. **Research the topic again** — do not assume the original research was complete
4. **Update facts** — re-verify every volatile figure against current sources
5. **Identify new evidence** — what exists now that did not when this was written
6. **Create new original value** — the rebuild must add something the old version
   did not have. If it cannot, this is a MERGE or HOLD case, not a rebuild.
7. **Redesign** — new structure driven by the argument; check against the corpus so
   the rebuild does not reproduce the site template
8. **Rewrite**
9. **Fact check**
10. **Pattern check**
11. **Quality check**
12. **Portuguese brief** → **human approval**

## Preserve
The URL, unless there is a strong reason to change it. Changing it costs inbound
links and indexation and requires a redirect decision.

## Update rule
`updatedAt` changes only because content changed. Record what changed in the commit.

## Never
Add words to clear a length threshold. If the honest article is shorter than the
original, publish it shorter.
