# Skill: Source Verification

## When to use
After research, before drafting; and again on every claim in a finished draft.

## Verify five things per claim
1. **Identity** — who published this
2. **Authority** — what tier, per `config/source-hierarchy.yaml`
3. **Date** — when published or last updated
4. **Support** — does it state *this specific claim*
5. **Scope** — does our wording exceed the source's

## The scope test
Read the source's sentence, then ours. If ours is broader, more certain, or more
precise, ours is wrong. Common widenings:

| Source says | We must not say |
|---|---|
| "may be beneficial" | "is required" |
| "approximately $425" | "$425" |
| "in the United States" | (unqualified, globally) |
| "management analysts" | "business analysts" |
| "one edition reported 16%" | "PMP holders earn 16% more" |

## Currency check
For volatile fields, ask what would have to be true for this source to still be
accurate. If a body changed something after the source's date, the source is
outdated regardless of how authoritative it is.

## Output
A verification table: claim, source, tier, date, verdict, note.

## Never
Mark verified what could not be reached. Record **UNVERIFIED** and explain.
